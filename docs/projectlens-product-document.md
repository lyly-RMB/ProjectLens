# ProjectLens 项目说明

本文是 ProjectLens 当前实现的项目介绍入口。它描述代码已经提供的能力和默认边界；阶段计划、目标架构和设计稿不覆盖本文。

## 一句话定义

ProjectLens 是一个把研发项目事实、权限和 Agent 调查流程放在同一个运行时里的项目协作服务。用户提出问题后，系统先确定“这个人在哪个项目、能看什么”，再检索证据、驱动 Hermes 工具循环，并输出带来源边界的回答。

## 当前实现

- **ProjectSpace**：用 `config/projects/*.json` 描述项目、来源、连接器、飞书群、成员、角色和可见性策略。
- **证据与知识**：提供 SourceRecord/Evidence 检索、项目快照、时间线、变更影响、风险扫描、事实解析和知识缺口；向量与混合检索需要显式配置。
- **Hermes 运行时**：生产问答固定走 Hermes。ProjectLens 提供身份、权限、只读工具和上下文预算，Hermes 负责模型调用与工具循环。
- **记忆闭环**：反馈形成记忆候选、风险反馈或知识缺口，记忆进入审核队列，不会未经验证直接成为永久事实。
- **入口**：提供 FastAPI、MCP server，以及可选的飞书 HTTP 事件和 WebSocket 长连接。

## 默认边界

系统默认是只读调查与协作服务，不会自动改代码、开 PR、部署或回滚。模型调用、飞书真实发送、Wiki/Obsidian 写入、风险后台审查和工程执行都由独立配置开关控制，并应在部署环境中单独审查。

## 权限与问答路径

```text
用户问题 -> 身份与项目绑定 -> 角色/群聊/资源权限求交
-> 检索证据 -> Hermes 只读工具循环
-> 事实/推断/未知校验 -> API、MCP 或飞书回答
-> 审计、反馈与知识缺口
```

权限过滤发生在检索和工具调用之前，工具参数不能伪造操作者身份。运行记录会保留事件、工具调用、引用、模型用量和最终回答，便于回放与审计。

## 运维判断

服务由 `project_lens.main:create_app` 创建，默认使用 SQLite。安装开发依赖后运行 `pytest -q` 执行回归；启动服务后检查 `/health`、`/ready` 和 `/release-gate`。当本文与代码、配置模型或运行中的 OpenAPI 冲突时，以代码和接口行为为准。
