# ProjectLens 项目说明

## 一句话定义

ProjectLens 是一个把研发项目事实、权限和 Agent 调查流程放在同一个运行时里的项目协作服务。用户提出问题后，系统先确定“这个人在哪个项目、能看什么”，再检索证据、驱动 Hermes 工具循环，并输出带来源边界的回答。

## 为什么需要它

研发项目的信息分散在代码仓库、文档、任务、发布记录、群聊和运行信号中。普通聊天模型无法知道哪些资料属于当前项目，也无法可靠判断某条信息是否过期、是否对当前角色可见。ProjectLens 将其拆成可验证的运行时步骤：解析身份与绑定、计算有效访问范围、检索证据、驱动只读工具循环、校验事实与未知项，并记录运行轨迹。

## 当前实现

### 项目空间

`config/projects/*.json` 描述一个可接入的项目空间，包含项目标识、仓库和来源、连接器、飞书群绑定、成员角色、公开来源、角色策略和群聊可见性策略。项目切换通过配置完成，不需要复制 Agent 代码。

### 证据与知识

系统将外部资料转换为带来源和时间信息的记录，并提供关键词检索、授权过滤、项目快照、时间线、变更影响、风险扫描、事实解析和知识缺口。可选配置 embedding、向量索引和混合检索；Wiki 与 Obsidian 是受开关控制的派生目标，写入默认关闭。

### Agent 运行时

生产问答固定使用 Hermes 模式。ProjectLens 提供项目上下文、有效访问范围、只读工具和上下文预算；Hermes 负责模型调用与工具循环。一次运行会保留事件、工具调用、引用、模型用量和最终回答，便于调试与回放。

### 记忆与知识缺口

反馈可以形成记忆候选、风险反馈或知识缺口。记忆需要经过审核队列；知识缺口可查询、转移状态、生成摘要并交给项目成员处理。未经验证的回答不会直接变成永久事实。

### 飞书与 MCP

飞书支持 HTTP 事件和 WebSocket 长连接两种接入方式，可在群聊中触发项目问答并返回状态、引用和审计摘要。MCP server 为外部 Agent 提供受策略约束的 ProjectLens 工具接口。两种入口都必须通过部署侧身份和项目绑定，不能由请求参数自行声明身份。

## 不做什么

- 不把模型输出当作唯一事实来源。
- 不默认替用户改代码、开 PR、部署或回滚。
- 不允许未授权用户通过提示词或工具参数扩大读取范围。
- 不把规划文档、测试样例或本地演示数据描述成生产保证。

## 典型问答路径

```text
用户问题 -> 身份与项目绑定 -> 权限求交 -> 检索证据
-> Hermes 只读工具循环 -> 事实/推断/未知校验
-> API、MCP 或飞书回答 -> 审计、反馈与知识缺口
```

## 运维与验证

服务由 `project_lens.main:create_app` 创建 FastAPI 应用，默认使用 SQLite。安装开发依赖后运行 `pytest -q` 执行回归；启动服务后使用 `/health`、`/ready` 和 `/release-gate` 判断基础状态、依赖就绪情况和发布门禁结果。

本说明以当前代码、配置模型和测试为准。`docs/` 中标为“设计中”“待实施”“目标架构”的文件用于规划，不覆盖当前实现；当文档与运行中的 OpenAPI 或配置模型冲突时，以代码和接口行为为准。
